# Client-side protocol and storage (web/src/lib)

Loaded only when working in this folder. Relay-side rules (hello/presence, reserved frames) are in `relay-worker/CLAUDE.md`.

- Connection: the pairing secret (QR fragment) is turned by `deriveRoomKeys` (`crypto.ts`) into `{room, token, key}`. The socket URL uses only `room`; every (re)connect sends `{"type":"hello","role":"host"|"client","token"}` and the relay replies `{"type":"presence","count":N}` where N = number of **distinct roles** connected (0-2). `paired` = count 2 (the other device is connected RIGHT NOW). The host remembers it has paired before (`markPaired`/`wasPaired`) so the QR stays hidden while the phone is merely offline.
- Text is end-to-end encrypted. Sender: `encryptEnvelope(key, id, JSON.stringify({type:"text",id,text,ts}))` -> frame `{"type":"msg","id","iv","ct"}` (AES-256-GCM, fresh IV, `id` bound as authenticated data; keep `type` FIRST because the relay recognises envelopes by that prefix). Receiver: `parseEnvelope` -> `decryptEnvelope` (null on any tampering/wrong key) -> `parsePeerMessage` and require the inner id to equal the envelope id. Text <= 100k chars (`MAX_TEXT_CHARS`). Never send or accept plaintext text messages.
- Delivery to an absent device: the relay holds the envelope (see `relay-worker/CLAUDE.md`) and tells the sender `queued`/`delivered`/`rejected` (`parseServerMessage`; surfaced via `onNotice`). All host-side handling of incoming text lives in `TextInbox` (`text-inbox.ts`), which runs everything ONE JOB AT A TIME in arrival order and enforces: (1) `qack {id}` is sent ONLY after the clip is durably stored AND its id is durably remembered (`seen.ts`, ids only, 7 days / 2000 max, NOT cleared by Clear); if either write fails the clip is shown but not acknowledged, so the relay keeps holding it (`onUnsaved` warns the user); (2) an id seen before never touches the clipboard or history again (replay / lost-qack redelivery, even after Clear or after it fell out of the newest 30); (3) anything unreadable (wrong key, tampered, inner id != envelope id, not a text message) is dropped with `qack {id, drop:true}` so it isn't redelivered; (4) a redelivery of a clip still in memory is acknowledged without copying again. Then `{"type":"ack","id","copied"}` goes to the sender (a second ack with `copied:true` follows if the copy happens later). Sender-side states are the pure reducer in `text-state.ts`. The host stamps clips with its own clock (ignores the sender's `ts`). Never handle incoming text outside `TextInbox`, and don't read or write the clipboard from page callbacks.
- Unfocused tab (host): `writeText` fails when the tab isn't focused, so the clip is stored with `copied:false`, its id is added to the THIS-SESSION pending set, the tab title gets a marker (`titleFor`), and a generic desktop alert is raised if permitted (`AlertsToggle`; the alert never contains the text). On window focus / tab visible / alert click, `TextInbox.copyPending` copies the newest pending clip (`pickClipToCopy`, which only considers ids that arrived this session) and drops older pending ones (they stay in the list with a Copy button); `ClipStore.update` never resurrects a clip the user cleared meanwhile. The page builds the inbox lazily in an event callback (it reads refs that `useRoom` fills in, which the react-hooks lint rules forbid during render).
- `RoomConnection` reports `open` only after the relay's first `presence` frame (the relay ignores frames sent before it finishes verifying the hello), and `send()` refuses until then.
- Host history: last 30 clips (`MAX_CLIPS`) in IndexedDB (Dexie, `clips.ts`), shown newest first with a Copy button each and a Clear button. All history changes go through `ClipStore` (`clip-store.ts`), a serial queue: never write to the DB from a handler directly, or concurrent messages will clobber each other.
- File casting (phone -> laptop): control messages are JSON text (`file-start {id,name,mime,size,chunks}`, `file-ack {id,ok,reason?}`, `file-abort {id}`; validate with `parseFileMessage`); data is binary frames `[16-byte uuid][4-byte BE chunk index][<=64 KB payload]` (`encodeChunk`/`decodeChunk`). Limits: 25 MB per file (`MAX_FILE_BYTES`), max 2 concurrent incoming transfers, 60 s idle timeout per transfer on the host. Sender (`sendFile`) applies backpressure on `bufferedAmount`, reports only transmitted bytes as progress, and resolves only when the socket has drained (data has left the phone, NOT arrived: relay delivery lags well behind); it aborts only if the queue stops shrinking for 30 s. The host sends `file-progress {id,received}` at most once a second so the phone shows real arrival progress; the phone fails a transfer only after 30 s with no progress/ack (`STALL_TIMEOUT_MS`), and a late ok ack still turns a timed-out transfer into delivered. `FileReceiver` tolerates duplicate/out-of-order chunks and rejects malformed ones. Over a real link delivery time varies a lot (3 MB took 1-10 s), so never treat "queued" as "delivered": wait for `file-ack`.
- Host stash: files live in IndexedDB (`files` table, Dexie v2 in `db.ts`), capped at 20 files / 200 MB (`pickEvictions`), changes serialized through `FileStore`/`SerialQueue`. Phone-side transfer states are a pure reducer (`transfer-state.ts`): files send one at a time (queued), a dropped connection fails queued/sending transfers immediately, and terminal states can't be overwritten by late events.
- File viewer (host): `viewKind` (`viewer-core.ts`) decides image / pdf / download-only from the sender's mime (extension only if the mime is missing/generic); SVG, HEIC and AVIF are deliberately download-only. Files are sender-controlled, so: images are only ever shown in `<img>` from a blob URL, and `checkImageBlob` (`image-info.ts`) reads the declared pixel size from the header and refuses anything over 50 MP (or unreadable) BEFORE decoding, for both viewing and thumbnails. PDFs render one page at a time on a canvas via PDF.js (`pdf.ts`, lazy-loaded, worker bundled from `pdfjs-dist`); canvas size is capped by `fitScale` (8192 px side / 40 MP) because page size x zoom x devicePixelRatio is attacker-influenced. `renderPage` allows one render per canvas (it cancels and awaits the previous one) and `openPdf` must be paired with its `destroy()`, including on failure, or PDF.js workers leak. Thumbnails are made on the host after the ack, one at a time, and stored on the file row (`thumb`).
- Host auto-copies with `navigator.clipboard.writeText`; this fails when the tab is unfocused, so the clip still lands in the list with `copied:false` and the ack tells the phone to say "tap Copy on computer".
- `RoomConnection` (`connection.ts`) handles reconnect with jittered backoff, heartbeat/dead-link detection, and immediate reconnect on tab-visible/online/pageshow.
- Tests run with `node --test` and type-stripping: no enums or constructor parameter properties in files under test; import siblings with the `.ts` extension.
